## 시작하기

Node.js **24.18.0** (`.node-version`) · pnpm **11.12.0** 기준. pnpm이 없으면 `corepack enable`
또는 `npm i -g pnpm@11.12.0`.

```bash
cd web
pnpm install
cp .env.example .env.local   # 최초 1회 — 값은 로컬 기본값 그대로면 된다
pnpm dev                     # http://localhost:3000 → /home 으로 리다이렉트
```

### 앱 폴더 컨벤션 (`src/`)

| 폴더                  | 역할                                                                            |
| --------------------- | ------------------------------------------------------------------------------- |
| `app/`                | 라우트. **페이지는 얇게** — 화면 본문은 `features/`에 두고 페이지는 조립만 한다 |
| `app/api/**/route.ts` | Next 서버 핸들러 (패턴 앵커: `app/api/ping/route.ts`)                           |
| `features/<도메인>/`  | 도메인별 화면·훅·스토어 (예: `features/broadcast/`, `features/clips/`)          |
| `components/`         | 도메인을 넘어 재사용하는 공용 UI (예: `components/app-shell/`)                  |
| `lib/`                | 공용 유틸·설정 (도메인 무관)                                                    |
| `api/`                | 백엔드 API 클라이언트 계층 (fetcher·쿼리 정의)                                  |
| `stores/`             | 전역 클라이언트 상태 (Zustand — 서버 데이터는 TanStack Query가 담당)            |

**새 코드는 어디에 만드는가:**

- **새 화면** → `app/<경로>/page.tsx`(얇게) + 본문은 `features/<도메인>/`
- **2개 이상 도메인에서 쓰는 컴포넌트** → `components/` (한 도메인 전용이면 그 `features/` 안에)
- **범용 함수·상수** → `lib/` · **백엔드 호출 코드** → `api/`
- 시각적 기본 요소(버튼·입력 등)는 만들지 말 것 — 먼저 `src/ui/`(`@/ui`)에서 찾는다

**치지직 콜백 계약.** `/oauth/chzzk/callback`은 `(dock)` **밖**이라 `AuthGuard`가 덮지 않는다 — 세션 판정은 화면이 직접 하고, 세션이 없으면 로그인으로 보낸 뒤 `/settings/channels`로 되돌아온다. 이 경로는 백엔드 `CHZZK_REDIRECT_URI`, 그리고 **치지직 개발자 센터에 등록된 redirect URI**와 **정확히 같아야 한다** — 개발자 센터는 앱당 하나만 등록하므로 환경마다 앱을 따로 판다. 프론트에 치지직용 env는 없다(동의 URL을 백엔드가 조립한다). 어긋나면 개발 빌드 콘솔에 경고가 뜬다(`chzzkOAuth.warnIfCallbackMismatch`) — 그게 없으면 증상이 "동의를 다 마친 뒤 낯선 주소에서 막힘"으로만 나타난다.

**전체 화면 계약.** 클립 편집기는 `(dock)`이 아니라 `(fullscreen)` 그룹에 둔다 — 시안 1d는 하단 독 없이 타임라인이 화면 바닥에 붙는 작업 화면이다. 두 그룹의 차이는 Dock 하나뿐이라 로그인 가드는 `(fullscreen)/layout.tsx`가 똑같이 덮는다. 독이 없으니 **나가는 길은 화면이 직접 내야 한다** — 편집기 헤더의 「보관함으로」가 그 자리다. `/clips`는 `(dock)`에, `/clips/editor`는 `(fullscreen)`에 있지만 URL 경로가 겹치지 않아 충돌하지 않는다.

**탈퇴 완료 계약.** `/goodbye`도 `(dock)` **밖**에 둔다 — `AuthGuard`는 refresh 토큰이 비는 순간 `/login`으로 보내므로, 탈퇴 직후 상태인 이 화면은 가드 안에서는 뜰 틈이 없다. 탈퇴 확정은 `markIntentionalLogout()`을 먼저 찍어 이 경로가 복원 경로로 남지 않게 한다 (POK-206). 탈퇴 확정은 실제 `DELETE /api/auth/me`다(POK-171, 방송 기록까지 지우는 것은 POK-256).

**계정 화면 계약.** 표시 이름·프로필 사진은 auth 서버에 저장된다(`PATCH /api/auth/me` · `PUT /api/auth/me/photo`, POK-208 ← 서버 POK-207). 두 응답이 `GET /api/auth/me`와 같은 모양이라 `['auth','me']` 캐시를 통째로 덮는다 — 헤더·사이드바가 재조회 없이 따라온다. **로컬·CI에서 사진 업로드는 503(`PHOTO_STORAGE_DISABLED`)이 정상이다** — auth의 `PROFILE_PHOTO_*` env가 비면 사진 기능만 꺼진다(`services/README.md` 「사진 창고 다섯」). 배선 버그가 아니다. 사진 주소(`profileImageUrl`)는 서버가 준 것을 그대로 쓴다 — `token` 쿼리가 서명값이라 조립하지 않으며, `null`이면 이니셜을 그린다. 사진 모달의 단계는 시안 1p(선택→업로드→크롭)와 달리 **선택→크롭→업로드**다 — 서버가 잘라낸 최종 그림만 받는다.

**플러그인 화면 계약.** 웹은 플러그인의 지금 연결 상태를 모른다 — 플러그인은 대기 중 서버에 신호를 보내지 않고, 웹은 OBS 안 루프백 독에 닿을 수 없다. 그래서 시안 1m 상단의 상태 배너·「연결 진단」 버튼은 두지 않는다 — 코드 입력 결과는 OBS PokeClip 독이 보여 준다. `GET /api/stream-keys`의 `issued`는 **키 발급 여부이지 연동 여부가 아니다** — 키는 첫 코드 발급 때 생긴다(서버 `ensureKey`). 웹에서 실시간 상태를 보이려면 플러그인 → 서버 신호 계약부터 새로 만들어야 한다(4B·4D 수신부 뒤로 보류).

**플러그인 다운로드 (POK-379).** 하단 배너 → 「플러그인 다운로드」 창에서 OS별 설치 파일을 받는다. 주소는 `src/lib/pluginDownload.ts`의 **고정 상수**다 — 웹은 GitHub Release를 조회하지 않는다. 정식 배포 전까지는 mono 공개 저장소의 `obs-plugin-v<판>` Release 파일(`pokeclip-obs-<판>-windows-x64-installer.exe`·`-macos-universal.pkg`)을 가리키고, **새 판을 내면 `PLUGIN_VERSION`을 올려 웹을 다시 배포한다**(Release가 먼저 공개돼야 링크가 404가 아니다). 정식 배포 때 S3 + CloudFront로 옮기면 `PLUGIN_DOWNLOAD_BASE`만 바꾼다 — mono를 비공개로 돌리면 Release 파일은 멤버만 받으니 그 전에 옮긴다. 다운로드 창의 기본 탭은 감지한 OS(모르면 Windows)이고, 파일 링크는 `target` 없이 연다 — GitHub가 `attachment`로 줘서 페이지가 바뀌지 않는다. 창은 실제로 하는 순서대로 세 단계(받기 → OBS 끄고 설치 → 독에 연동 코드)를 세우고, 다운로드 버튼은 1단계·서명 경고는 막히는 2단계 안에 둔다. 설치·연결 상태는 그리지 않는다. 누른 수는 `plugin_download_clicked`(받은 수 아님).

**clip 서버 연결 (POK-251).** 홈·라이브·지난 방송·편집기·보관함은 clip 창구에서 실제 값을 받는다. 요청은 전부
로그인 세션의 `apiFetch`를 거친다(Bearer·401 회전) — clip 거절 사유(`{error, field}`)는 `ApiError.code`·`field`로 오고,
`src/api/clipEditor.ts`가 `ClipApiError`로 옮긴다(예: 409 `source_not_ready`). 규칙 넷:

- **목업은 기본값이 아니라 주입값이다.** 편집기·지난 방송·보관함 훅은 시안 목업을 시험·스토리북용 고정 데이터로 옮겼다
  (`vodListFixture.ts`·`libraryFixture.ts`, 편집기는 `source`를 안 주면 목업). 실제 화면은 서버 값만 그리고, 줄 백엔드가
  없는 칸(AI 자막·제목 추천·이미지·BGM)은 **「준비 중」**이라고만 말한다. 가짜 값을 지어내지 않는다.
- **방송이 없으면 꺼짐 화면이다.** 라이브 화면은 10초마다 「방송 중」 목록을 다시 물어(`useLiveStreamSelection`)
  없으면 `LiveOfflineScreen`을, 생기면 새로 고침 없이 대시보드를 그린다. `?mock=offline`은 개발 전용 시안 토글로 남았다. 주소의
  `?stream=`은 Next 주소 값으로 읽어 같은 화면에서 바뀌어도 그 방송으로 옮긴다(POK-254). 대시보드는 카드 3초·차트와 방송 정보
  10초마다 읽는데, 끝난 방송은 차트·방송 정보를 끝난 지 2분이 지난 뒤 한 번 받으면 멈추고(수집기의 마지막 적재를 기다린다) 카드 목록만 1분마다 읽으며 통로에 다시 붙지 않는다(POK-254).
- **영상이 없으면 흉내 내지 않는다.** 플레이어는 소스가 없으면 「영상 신호 없음」 자리를 그린다. 재생 흉내·가짜 채팅
  오버레이는 `simulate`를 켤 때만(스토리북·시험) 돈다. 수동 마킹도 흉내 내지 않는다: 라이브의 단추·F8은 누른 때·보낸 때를
  `POST /api/clip/broadcasts/{streamId}/marks`로 보내 서버가 카드를 만들고(POK-392), 답이 올 때까지만 「카드 만드는 중」 자리가 선다.
  지난 방송은 정보줄의 「이 시점 카드 추가」(시안 1c, 「재생 지점 앞 40초 · 뒤 20초」)와 F8이 **녹화 재생기의 정확한 자리**를
  `positionMs`(초 × 1000 반올림, 서버 기준점 축)로 보내고, 통로가 없어 답의 카드를 목록에 바로 넣는다. 200(20초 안 앞 카드)이면
  알리고 그 카드로 옮긴다. 녹화가 없거나 기준점을 몰라 녹화 시작 축이면 단추가 꺼진다(재생기가 그 축의 자리를 못 준다).
  갈래는 명부가 답한 상태로만 고르고, 상태를 모르는 동안(지난 방송 주소도)은 단추가 꺼지고 F8은 확인 중이라고만 알린다.
- 🔴 **시각 기준점 (POK-255).** 카드·조각의 ms는 방송 시작 편지가 아니라 **녹화 첫 조각** 기준이다. clip이 방송 줄에
  `timelineOriginAt`으로 그 절대 시각을 실어 준다. **편집기**는 서버 기준점 → 녹화 재생 서버 첫 구간 → 방송 시작 시각 순으로
  고른다(`timelineBaseMs`, 렌더가 조각을 자르는 축과 같아 서버 값이 정본). 미리보기 영상도 「기준점 + 초」로 묻는다 — 조각 장부의
  위치 값은 방송을 넘어 이어져서 「녹화 시작 + 초」는 두 번째 방송부터 틀린다. **라이브 화면**(지난 방송 채팅 시점·차트의 카드
  자리)은 **다시보기 플레이어의 축**을 먼저 쓴다(`timeBaseOf`) — 채팅이 영상과 맞아야 한다. 플레이어는 서버 기준점에 선다
  (`rebaseTimeline`, POK-253 — 전에는 녹화 시작에 서서 두 시작의 차만큼 카드와 영상이 어긋났다). 조각이 아직 없는 방송은 서버가
  `null`을 주고 그때만 방송 시작 시각으로 대신한다(수십 초 어긋날 수 있다).
- 🔴 **녹화는 구간 여럿일 수 있고 재생 서버는 틈을 건너 주지 않는다 (POK-253).** 송출이 끊기거나 녹화기가 다시 서면 한 방송의 녹화가
  구간 여럿이 된다. 재생 서버(`{base}/get`)는 틈을 건너는 요청을 **틈 앞에서 끊고**, 틈 안에서 시작하는 요청은 **404**다(로컬 실측).
  그래서 `recordingTimeline`이 **방송 시간 [시작, 종료]와 실제로 겹치는** 구간들(여유 없음 — 여유를 두면 같은 키로 그 안에 이어

  접으면 틈 뒤 카드가 어긋난다)에 놓고, 다시보기는 **한 구간씩** 받아 끝나면 다음 구간을 이어 튼다(틈을 누르면 다음 구간 시작).
- 🔴 **영상 요청은 출입증을 받은 뒤에만 쿠키를 싣는다 (POK-317).** CDN 뒤(prod) 영상은 clip이 주는 CloudFront 서명 쿠키가
  없으면 403이다. **출입증은 `src/api/playbackAccess.ts` 한 곳에서 받는다**(라이브 화면 · 지난 방송 목록 · 편집기 · 다시보기 모두).
  받는 길이 둘이면 쿠키 셈과 403 처리가 한쪽만 보게 되어 고친 자리 옆에 구멍이 났다(PR #332 봇 리뷰 1~3판).
  - 라이브 화면은 1분마다 `ensureLiveAccess`로 본다(쓸 만하면 요청 없음, 만료 5분 전이면 새로 받음). **받음이나 필요 없음(503) 답이
    오기 전에는 라이브 주소를 재생기에 넘기지 않는다**. 먼저 넘기면 첫 요청이 쿠키 없이 403이고 hls.js는 한 번만 다시 시도한 뒤 멈춘다.
    열린 뒤 갱신이 실패하다 회복했거나 다른 화면이 403으로 출입증을 버린 뒤 다시 받으면 재생기를 새로 세운다.
  - 편집기는 녹화 목록을 묻기 직전에 `ensurePlaybackAccess(방송 번호, 영상 키)`로 받는다. 만료 5분 전까지 다시 쓰고(영상 키가
    바뀌면 다시 받는다), 미리보기 창은 `ensureMediaAccess(영상 키)`로 갱신한다. 출입증을 못 받으면 「녹화 없음」으로 열지 않고 다시
    열라고 알린다.
  - 지난 방송 목록은 녹화를 확인하기 직전에 `ensurePlaybackAccessForList`로 받는다. 키마다 쿠키 12장이라 **한 탭에 든 키는
    12개까지**(144장, 크롬 도메인당 약 180장)이고, 빈자리만큼 한 번도 안 해 본 키, 그다음 오래전에 해 본 키(실패 포함) 순으로 차례를 준다. 차례가
    안 온 키는 쿠키 없이 묻고 다음 주기에 다시 온다. 라이브 화면의 녹화 조회도 출입증 답 뒤에 한다.
    상한은 라이브 화면 · 편집기가 받은 출입증까지 센다. 쿠키 경로가 영상 키라 **영상 키로 센다**(같은 송출 키로 한
    방송 여럿은 한 칸, POK-411). 탭마다 셈이 따로라 탭을 여럿 열면 한도를 넘길 수 있다.
  - **어느 영상 요청이든 403이면 쿠키가 지워진 것으로 보고 그 키의 출입증을 버린다**(`reportPlaybackForbidden`): 녹화 목록은 응답
    코드로, 편집기 미리보기는 버린 뒤 다시 받아 한 번 더 부르고, 다시보기 `<video>`는 응답 코드를 못 읽어 오류가 나면 첫 바이트를
    물어 403일 때만 다시 받아 같은 줄기를 다시 붙인다(줄기마다 한 번). 라이브 hls.js는 치명 오류의 응답 코드가 403이면 한 번 더
    해 보지 않고 버린다(POK-410). hls.js가 없는 브라우저(옛 iOS Safari)의 기본 재생은 다시보기처럼 첫 바이트를 물어 본다. 라이브 화면은 1분 안에 다시 받고 재생기를 새로 세운다. 새로 선 재생기가 영상 조각을 하나도 못 받고 또 403이면
    더 받지 않고 「영상에 접근할 수 없어요」로 멈춘다(계약3 재시도 정책, POK-419). 원인이 다른 탭이든 쿠키 한도든 사용자가
    지운 것이든 스스로 낫는다.
  - **재생이 멎으면 까닭을 알린다(POK-337).** 영상을 아직 못 부른 자리는 영상 자리 아랫줄이(라이브 출입증을 처음부터 못 받음 ·
    다시보기 녹화 목록을 묻지 못함), 틀던 영상이 멎은 자리는 영상 위 한 줄 덮개(`playbackError`)가 알린다(라이브 403 · 라이브 복구
    포기 · 다시보기 줄기를 다시 붙일 수 없음). 편집기 미리보기의 재생 오류는 아직 알리지 않는다.
  - 쿠키는 **출입증이 실제로 발급된 뒤에만** 싣는다(`mediaCredentials()`: 녹화 목록·미리보기 fetch는 `credentials`, 라이브
    hls.js는 `xhrSetup`의 `withCredentials`, 다시보기 `<video>`는 원래 싣는다). 로컬·dev 영상 서버(MediaMTX)는
    `Access-Control-Allow-Origin: *`로만 답해 쿠키를 실으면 브라우저가 응답을 버리기 때문이다(2026-10-23 실측).
    🔴 **로컬은 clip 출입증 설정 셋(`CLOUDFRONT_KEY_PAIR_ID` · `CLOUDFRONT_PRIVATE_KEY_PEM` · `MEDIA_BASE_URL`)을 비워 두는 것이
    기본이다.** 채우면 출입증이 실제로 나와 쿠키를 싣는데, 라이브(`:8888`)는 다른 출처라 막힌다(녹화는 `/media` 같은 출처 전달이라 된다).
    출입증 흐름을 로컬에서 시험할 때만 켠다.
  - 503 `playback_signing_unavailable`(서명 재료 없음, 또는 그 방송의 영상 키가 정책에 못 들어감)을 받은 **방송은** 더 묻지 않는다.
    자격 확인이 안 되는 503(`authorization_unavailable`)은 실패라 다시 묻는다.
    보관 기간(60일)이 지난 방송은 출입증 문이 410 `vod_expired`라 「만료」로 받아 그 방송은 더 묻지 않고, 지난 방송 화면 · 편집기가
    「보관 기간(60일)이 지나 … 볼 수 없어요」로 알린다. 렌더 주문의 410도 편집기가 같은 뜻으로 알린다(POK-335).
  - 🔴 **녹화 주소는 쿠키 경로 아래다**: `{base}/playback/{키}/list` · `/playback/{키}/get?start&duration&format`. 재생 서버의
    `path` 쿼리는 싣지 않는다. 쿠키 정책은 쿼리를 못 막아(`/playback/{내키}/list?path={남의키}`도 맞는다) 엣지가 경로의 키로
    `path`를 채우고 **들어온 `path`는 버린다**. 로컬은 `app/media/playback/[key]/[op]/route.ts`가 같은 규칙으로 재생 서버에
    넘긴다(`MEDIA_PLAYBACK_ORIGIN`이 있을 때만, 없으면 404).
- 🔴 **영상 주소는 방송 번호가 아니라 영상 경로의 키로 만든다 (POK-233).** 1번이 편지의 방송 번호를 방송마다 새 회차 번호로
  바꾸면 라이브·녹화 경로(스트림키)와 갈린다. clip이 방송 줄에 `ingestStreamId`를 실어 주고, 라이브 LL-HLS·녹화 목록·다시보기·
  편집기 미리보기는 `mediaStreamId(row)`(= `ingestStreamId`, 없거나 비면 방송 번호)를 쓴다. **API 경로·출입증·채팅·카드는 방송
  번호 그대로다.** 주소의 `?stream=`도 방송 번호라 영상 경로로 바로 쓰지 않는다(`useMediaSource`는 넘겨받은 키만 본다).
  편집기 미리보기 창은 구간의 시작이 든 녹화 구간 안으로 자른다(틈을 건너는 카드는 틈 앞까지만 보이고, 구간 자체에 녹화가 없으면
  여유가 다음 녹화에 닿아도 받지 않고 미리보기 실패로 알린다). 구간 시작은 **ms 올림**으로
  읽는다 — 재생 서버가 마이크로초까지 주는데 내리면 두 번째 구간부터 0.2ms 틈 안으로 들어가 404다(`parseSpanStartMs`). 시크바는
  녹화 길이 그대로다(1시간 상한은 라이브 창을 만드는 쪽만 건다). 왼쪽 끝은 축의 0초(서버 기준점)가 아니라 녹화 처음이다(POK-474):
  송출 회차가 방송 여럿을 넘어 이어지면 기준점이 몇 시간 앞에 서서, 0초부터 그리면 녹화가 오른쪽 끝에 몰렸다. 다시보기의 오른쪽 끝 단추는 「끝으로」라고 말하고 녹화 끝으로
  가며(라이브에서는 「실시간으로」, 재생 계약의 `replay`), 보이는 볼륨(70%)을 영상에 싣는다. 지난 방송 화면의 **글자**는 라이브
  문구를 쓰지 않는다: 채팅 기록 · 방송 통계 · 「끝날 때 N명 시청」 · 플레이어 「지난 방송 영상」(녹화를 확인하는 동안 「녹화 영상을
  확인하고 있어요」, 없으면 「녹화 영상을 찾지 못했어요」. 재생 서버가 없거나 묻지 못하면 「영상 서버에 아직 연결되지 않았어요」라고 하고,
  지난 방송 목록처럼 「있음」만 굳혀 없거나 묻지 못했으면 1분 뒤 다시 묻는다) · 제목 자리 「지난 방송」 · 경과 자리 「방송함」 ·
  채팅 바닥 「마지막 메시지까지
  보는 중」(영상 시각을 따라가면 「0:47:22 시점까지 보는 중」, 그 시점을 아직 모르면 「시점을 확인하는 중」), 감지 안내 없음. 값이 없는 자리의 말은 한 함수(`missingWord`)가 정한다: 모르면(받기 전, 상태를 모름, 명부에
  없음) 「확인 중」, 끝난
  방송에 없으면 「기록 없음」, 라이브에서 받았는데 아직 못 쟀으면 「수집 전」. 시청자 기록은 정보 바와 통계가 같은 규칙으로 믿는다
  (`trustedViewerSeries`). 문구를 내는 곳은 전부 대시보드가 만든 화면 상태(지난 방송 주소면 명부가 방송 중이라고 답하기 전까지 끝난 방송,
  `usePathname`)를 받는다. 시청자 수는 라이브·지난 방송 모두 마지막으로 잰 값이다(빈 관측은 건너뛴다, 통계의 최고·평균과 같은
  규칙). 채팅 수 이름과 그래프 끝은 차트가 **실제로 읽은 창**(`LiveChart.scope`)을 따른다: 방송 전체면 「방송 중 채팅」·끝난 시각,
  12시간 넘는 방송과 시작 시각을 모르는 지난 방송은 끝 12시간만 읽어 「마지막 N분 채팅」. 라이브도 방송 처음부터 지금까지 읽어
  「방송 중 채팅」·「지금」이고, 시작 시각을 모르는 라이브(자리표시 방송)만 지금 기준 최근 10분이라 「최근 N분 채팅」·「지금」이다.

  창 하나만 다시 묻는다. 라이브 시청자 기록도 처음 한 번만 시작부터 받고, 그다음은 받아 둔 마지막 관측 2분 앞부터만 받아
  이어 붙인다. 통계 그래프(`LiveStatsPanel`·`statsChart`)는 한 상자 두 층이다: 위 시청자 선 · 아래 채팅 막대, 층마다
  눈금이 따로라 두 값을 한 눈금에 겹치지 않는다. 2분 칸이 14px(--pc-u 배율)보다 좁아지면 가로 스크롤로 바뀌고 칸을 2분으로

  낭독기). 한 번에 50쪽을 읽으면 1초 쉬고 이어 읽는다(요청이 쏟아지지 않게. 실패가 아니다: 실패로 두면 받는 동안 →를 연타할 때

  옮기면(영상 없이 누른 카드, 녹화의 시크바·키·끝으로·카드·다 본 뒤 처음부터) 채팅 창이 그 시점(맨 아래)을 따라가고, 녹화를
  늦게(1분 재조회로) 찾아 채팅이 그 재생 위치로 통째로 바뀔 때도 따라간다. 재생으로 흐르거나 녹화 틈을 넘을 때는 읽던 자리를 지킨다. 채팅이 영상 시각을 따르지 않는
  방송(기준점 없는 자리표시)은 카드를 눌러도 읽던 자리를 지킨다. 다시 세우지 않으므로 목록의 포커스도 남는다. 급증 키워드도 그
  시각 앞 2분으로 센다(시점을 아직 모르면 비운다: 라이브가 끝나 녹화를 기다리는 동안 라이브 때 키워드가 남았다). 재생기는 카드 시각에 정확히 서고(`seekToPosition`, 시크바 비율을 거치면 1초 안쪽 앞에 섰다), 옮긴
  자리의 줄기가 붙기 전에는 옛 줄기가 흐르거나 끝나도 그 시각으로 자리를 되돌리지 않으며, 화살표는 옮기는 중이면 그 도착점에서
  센다. 옮기는 중에 재생을 누르면 옮긴 자리부터 튼다(다 본 뒤라도 처음부터로 덮지 않는다). 처음 자리는 0초가 아니라 첫 구간
  시작이다. 녹화도 시작 시각을 모르면

  표시를 달고 hls.js가 앞 조각을 조각 길이로 메운다, 둘 다 확인함). 재생 위치가 목록의 첫 조각보다 앞이면 첫 조각에서 거꾸로
  센다: 1시간 창은 조각이 생길 때마다 맨 앞 조각을 버려 맨 앞을 보던 재생 위치가 목록 밖으로 밀리고(로컬·dev MediaMTX는 4초 ×
  900 = 정확히 1시간), 모른다고 하면 Home·1시간 넘은 카드로 되감은 뒤 멈추면 4초 안에 채팅이 최신으로 튀었다. hls.js
  `playingDate`는 쓰지 않는다: 재생 위치가 0이면 직전 자리의 시각을 줘 시작 직후·맨 앞으로 옮긴 직후 시차와 다른 자리를 가리켰다. 재생 위치에 영상이 있을 때(`readyState` ≥
  HAVE_CURRENT_DATA)만 재고 재생 위치·실시간 끝의 시각과 시차를 한 순간에 같이 잰다(`livePosition`): 첫 조각이 붙기 전(재생 위치
  0초)에 재면 라이브를 여는 순간 1시간 되감은 것처럼 따라갔고, 따로 알리면 새 시차에 옛 시각이 붙었다. 시각은 정각 초로 내리지
  않고 같은 실제 초 안에서 시차도 같으면 앞 값을 둔다(초당 한 번 알린다): 카드 0초(서버 기준점)는 ms 자리가 있어 정각 초로
  내리면 카드로 정확히 옮겨도 바닥이 1초 일렀다. 시각을 모르거나(사파리
  기본 재생기 등) 방송 시작 시각을 모르면 따라가지 않는다. 읽기는 지난 방송과 같은 로더이되 위 끝이 「표에 다 들어온
  자리」(실시간 끝의 시각 − 보정 − 적재 여유 3초, `liveSettledUpTo`)라 시간이 가며 움직인다: 그보다 늦은 줄은 아직 표에 없을 수
  있어 읽어 「다 읽음」으로 두면 영영 빠진다. 보정은 차트가 받은 값(없으면 3.9초)이고 실시간 끝의 시각도 영상 서버 시계 축이다
  (브라우저 시계를 믿지 않는다). 이 자리는 짐작이라, 이어 읽을 때 다 읽은 끝을 10초(`LIVE_REREAD_MS`, 라이브 폴링과 같은 값) 겹쳐
  다시 읽고 지문으로 거른다(POK-254): 적재가 여유보다 늦어 한 번 빠진 줄도 다음 읽기에서 잡는다. 그보다 더 늦으면 여전히 빠질 수
  있다(수집기가 답에 「표에 다 적은 시각」을 실으면 닫힌다). 위 끝이 2초 넘게 앞서야 더 읽고(매초 묻지 않는다), 보이는 시각은 위 끝 5초 앞까지로
  자른다(`liveShownUpTo`: 실시간 가까이에서 읽는 동안 「불러오고 있어요」로 깜박이지 않는다. 답이 2초 넘게 늦으면 깜박일 수 있다).

  돌아오면 치운다: 쥐고 있으면 아무도 보지 않는 읽기가 이어졌다(실패하면 10초마다 다시 묻고, 뜸한 방송은 앞 덧붙이기를 끝까지

  동안에도 중계·폴링은 그대로 받아 실시간으로 돌아오면 최신 줄이 바로 보인다(그래서 실시간 10~40초 뒤를 보는 동안 채팅 요청은

  시각 기준이고(분당 수는 그 앞 1분의 줄 수), 바닥은 「1:23:51 시점까지 보는 중」이다. 라이브에서는 채팅이 영상을 따르는 동안
  사람이 옮기면(실시간으로 포함) 채팅 창이 맨 아래로 가고, 옮기지 않아도 따르기가 바뀌면(영상이 처져 10초 이상) 맨 아래로 간다.

  옮긴다(그 길은 숨은 탭에서 아직 밀린다). 되감을 구간이 없으면(영상 서버가 다시 붙어 목록이 막 새로 섬) 경과 시계로 옮길 때처럼

  「기록 없음」으로 읽었다. 늦게 온 답(방송이 바뀌었거나 읽는 동안 방송 상태가 바뀐 옛 창의 답)은 버린다. 저장소(`liveDataStore`)는
  방송 번호가 바뀌면 앞 방송의 값을 통째로 버리고, 라이브 화면은 저장소를 비운 뒤에야 그린다(첫 그림이 앞 방송의 값을 칠하고 그
  효과들이 앞 방송으로 요청을 보냈다). 비우기 전 첫 그림도 빈칸이 아니라 빈 상자다: 비어 있으면 Next 스크롤 처리기가 잡을 화면이
  없어 맨 위로 올리지 못했다. 명부에서 사라진 방송(위임 회수·탈퇴)은 시각도 비워 「방송 중이 아니에요」 옆에서 경과가 흐르지 않는다.
  시각 신호(통계 그래프 끝 「지금」과 시청자 선 끝의 깜박이는 점, 녹화 끝에서 깜박이는 점, 맨 앞 카드 강조)와 라이브 채팅 바닥의 「최신 메시지 따라가는 중」은
  그대로다(디자인 몫. 라이브를 되감은 동안의 바닥은 「그 시점까지 보는 중」이다, POK-326). 영상이 없을 때 카드를 누르면 「영상은 아직 없어요」(녹화가 없다고 확인된 방송은 「녹화 영상이 없어요」)라고
  알리고, 채팅이 그
  시점으로 가는 지난 방송만(시점을 절대 시각으로 바꿀 기준점이 있을 때) 「채팅을 그 시점으로 옮겼어요」를 붙인다. 녹화는 화면을 연
  뒤에 찾으므로, 라이브로 밝혀지기 전에 고른 시점(카드·주소의 `?card=`)은 플레이어가 못 옮긴 시점으로 남겨 녹화의 **시작 위치**로
  넘긴다(`startAtSeconds`, 녹화가 받으면 비운다). 라이브에서 고른 시점은 영상 시작 위치도 채팅 시점도 남기지 않고, 라이브로
  밝혀지면 모르는 동안 고른 것도 비운다: 남기면 방송이 끝난 뒤 녹화는 처음부터인데 채팅만 그 카드에 묶였다. 녹화 재생은 기다리던
  이동의 타이머를 언마운트 때 지우지 않는다: 지우면 개발 서버(StrictMode)가 새로 선 부품을 껐다 켤 때 그 이동이 사라져 처음부터
  틀었다(실기동에서 찾음).
  플레이어 가위 단추는 서버로 보내는 길이 없어 「준비 중」이라고만 한다. 화질·저지연 설정 메뉴는 실재생(라이브·다시보기)에서
  안 보인다 — 렌디션이 하나라 고를 것이 없다(계약3 2절, 목업 재생에서만 보인다).
- **카드에는 편집 · 가리기 (POK-393 · POK-463).** 카드 찜(집기·놓기)과 「편집 중」 배지를 없앴다(POK-393).
  **가리기는 POK-463에서 되살렸다**: 카드 줄의 눈 가림 아이콘(「이 카드 가리기」)을 누르면 카드가 「숨김 N」 칸으로 옮겨 가고 전체·자동·수동 칸,
  통계 지표·그래프 핀에서 빠진다. 「숨김」 칸의 카드에는 「되살리기」만 있다(가린 사람이 아니어도 된다). 이유는 묻지 않는다. 가리기 답(바뀐 카드)을
  바로 목록에 넣어 끝난 방송도 다음 목록 읽기(1분)를 기다리지 않고, 같은 카드는 순번(`eventSeq`)이 낮은 판을 버려 늦게 온 옛 목록이 되돌리지 않는다.
  대시보드 목록·편집기는 `includeHidden=true`로 읽고(가린 카드도 편집기로 열린다), 홈·지난 방송 목록의 카드 수는 가린 카드를 뺀다. 「편집」은 서버를 부르지
  않고 바로 편집기로 간다. 여러 편집자가 같은 카드를 동시에 각자 편집한다. 시안의 카드 모양(점수 배지 · 원클릭 업로드 · 보관함 저장)은
  그대로다. 카드에서 연 편집기는 첫 저장에 그 카드 번호를 `?sourceCardId=`로 싣는다(계약6 본문은 그대로, 시범 운영 측정 재료:
  `services/README.md` 「시범 운영 측정 재료」). 옛 clip이 `claimedBy`를 실어 보내도 화면은 그 칸을 안 본다.
  편집기를 카드에서 열면 열기 기록(`POST /api/clip/jump-cards/{id}/open`)을 마운트당 한 번 보낸다(실패해도 편집은 된다).
  **배포 순서: clip을 웹보다 먼저 올린다**(POK-463). 새 웹이 옛 clip에 붙으면 가리기가 404로 실패하고(토스트) 「숨김」 칸은 늘 비어 있다.
- **「영상 만들기」 = 렌더 + 유튜브 바로 올리기 (POK-291).** 편집기의 「영상 만들기」는 **업로드 정보 창**(`UploadInfoDialog`)을
  연다: 제목 · 설명(5000바이트) · 태그(Enter·쉼표로 넣고, 공백 든 태그는 따옴표 두 글자를 더해 합계 500자) · 공개 범위(비공개 ·
  일부 공개 · 공개, 기본 비공개) · 아동용 · 썸네일(자동 · 완성 영상의 장면 · JPG/PNG 10MB 이미지). 「만들고 올리기」를 누르면
  (바뀌었으면 먼저 저장하고) 렌더 주문에 이 정보를 multipart로 싣는다(`request` 파트 JSON `{upload}` + 이미지면 `thumbnail` 파트).
  렌더가 끝나는 대로 **clip이 스스로 올린다**: 웹은 렌더 끝을 기다렸다 다시 부르지 않는다. 201은 새 주문, 200은 같은 판이
  만드는 중(끝나면 이 정보로)이거나 이미 만들어져 있음(바로 올림)이라 문구를 가른다. 창이 떠 있는 동안 편집기 단축키는 꺼진다.
  헤더와 상태 확인은 업로드가 끝날 때까지 간다(만드는 중 N% → 올리는 중 → 업로드됨 / 업로드 실패). 🔴 **고른 범위 그대로 올라간다**
  (근거와 단서는 `services/README.md` 업로드 절). 창과 보관함이 고른 범위로 누가 보는지, 공개면 구독자 알림, 바꾸는 곳을 알린다
  (`uploadInfo.ts` `privacyNote` · `libraryView.ts` `privacyNoteText`). 직접 고른 썸네일은 채널 전화 인증이
  있어야 붙는다. 장면 시각은 재생 위치가 완성 영상 안이면 그 자리, 아니면(녹화 없음 포함) 가운데에서 시작한다(`uploadInfo.ts`).
  카드로 연 편집기는 첫 저장 뒤 주소를 `?recipe={id}`로 바꾼다(`history.replaceState`): 새로고침해도 같은 편집본이 열려 다음
  저장이 편집본을 하나 더 만들지 않는다. 스스로 만든 번호면 다시 읽지 않아 실행취소 기록과 카드 창(구간 한계)이 남는다.
  🔴 **배포 순서: clip이 먼저 배포돼야 한다.** 옛 clip은 렌더 주문의 업로드 정보를 무시하고 렌더만 한다(201을 주니 화면은
  「올릴게요」라고 하지만 아무것도 올라가지 않는다).
- **보관함에서 유튜브에 올리고 영상을 받는다 (POK-111 · POK-291).** 진행 단계가 배지로 보인다: 만드는 중 → 올리는 중 →
  업로드됨(전에는 「발행됨」. 칩 이름은 그대로다) · 확인 필요 · 업로드 실패. **업로드 실패는 서버 상태가 아니다**: 서버는 완성으로
  돌려주고 웹이 「가장 최근 업로드가 실패」로 만든다. 업로드 실패의 「다시 시도」는 창 없이 **저장된 정보 그대로** 다시 올린다
  (`POST …/clips/{clipId}/uploads/retry`, 본문 없음). 유튜브가 거절(`YOUTUBE_REJECTED`)했으면 같은 정보는 또 거절될 수 있어
  「이어서 편집」에서 창을 열어 고쳐 올리라고 안내한다. 완성인데 창에서 고른 정보만 남고 업로드가 안 붙었으면(업로드가 꺼져
  있었거나 서버 경합) 「업로드」도 같은 다시 시도 문으로 그 정보대로 올리고, 패널 제목은 실리지 않으니 잠근다. 진행 한 줄은 패널의 「자막」 칸이 아니라 안내 자리에 선다. 업로드 정보 창
  없이 만든 옛 완성 영상은 지금처럼 「업로드」가 상세 패널의 제목으로 올린다
  (`POST …/clips/{clipId}/uploads`, 공개 범위를 안 보내 **비공개**). 승인 단계가 없어 편집자도 「업로드 요청」이 아니라 바로
  올린다. 제목 규칙(앞뒤 공백 뺀 1~100자, `<` `>` 금지)은 보내기 전에 재고, 보내는 동안 단추를 잠근다(서버도 같은 영상의
  살아 있는 업로드를 200으로 돌려준다). 업로드·다시 시도의 답은 「아직 올릴 수 있는 같은 영상」일 때만 얹는다(늦은 답이 더 새
  상태를 덮지 않는다, ADR-080 6번). 올리는 중·확인 필요는 누를 수 없는 단추로 바뀌고, 확인 필요는 채널을 보라고 안내한다
  (자동 재시도가 없다). 확인 필요는 사람이 푼다(POK-333): 「채널에 올라갔어요」는 영상 주소를 받아 발행됨으로, 「안 올라갔어요」는 두 번
  올라갈 수 있다는 경고 창을 거쳐 실패로 닫아 다시 올릴 수 있게 한다(마지막 시도에서 30분 전이면 서버가 거절하고 사유를 알린다). 옛 판의
  확인 필요 줄(「이전 판 vN」)에도 같은 단추가 붙는다. 답을 줄에 얹지 않고 목록을 다시 읽는다(`UploadResolutionControls.tsx`). 실패 사유를 패널에 보인다: 연동 끊김(`YOUTUBE_NOT_LINKED`·
  `UNLINKED`·`BROKEN`)은 채널 연동으로, 한도(`QUOTA_EXCEEDED`)는 내일로. 영상은 올라갔는데 썸네일만 못 붙였으면 그렇게 말한다
  (`THUMBNAIL_FORBIDDEN`이면 채널 전화 인증. 재배달이라 붙었는지 모르는 `THUMBNAIL_UNCONFIRMED`는 스튜디오에서 확인하라고). 일부 공개·공개를 골랐으면 그 범위로 올라가게 하는 단추(「다시 시도」·「업로드」·「렌더 재시도」)와 누가 보는지를 같이 알린다(편집 중이면 안 알린다). **미리보기 재생·다운로드**는 누를 때
  `POST …/file-access`로 60분짜리 서명 주소를 받는다(목록에 싣지 않는다). 「비율」은 패널을 열 때 상세를 읽어 레시피 출력의 비율로
  보인다(POK-254, 해상도는 칸이 없어 안 보인다). 패널에서 고친 제목은 올리기 전까지 화면의 초안이다
  (편집본에 제목 칸이 없다. 완성본만 고칠 수 있고 입력 칸 아래에 그렇게 알린다, 편집 중·렌더 실패는 잠근다: POK-254), 올린 뒤에는 업로드 제목이 편집본 제목으로 보인다. 홈 「발행 현황」·라이브 띠 「클립 완료」도
  같은 보관함 목록에서 센다. 「발행 현황」은 줄의 `liveUploads`(모든 판의 살아 있는 업로드)를 **업로드마다 한 줄**로 그린다:
  새 판 영상을 주문해 `latestClip`이 바뀌어도 옛 판으로 올린 영상이 남는다. 패널은 위쪽이 실제로 보이는 업로드(올리는 중·확인 필요·올림일 때의
  `latestClip.upload`, 올린 뒤 새 판을 저장만 한 「편집 중」이면 없음)를 뺀 나머지를 「이전 판 vN」으로 보이고 올림만 유튜브 링크다(POK-334, 칸을 모르는 옛 서버면 `latestClip.upload` 하나로 접는다).
- **화면에서 고른 모양 그대로 영상이 나온다 (POK-252).** 편집기는 레시피를 계약6 **v2**로 저장한다: 레이아웃
  (세로·분할·중앙·크롭)을 「층 + 바탕 + 구분선」으로, 칸마다 자르는 자리를 그대로 싣고, 편집본을 다시 열면 같은 모양으로
  되살린다(`features/clips/editor/recipeLook.ts`, 두 방향이 한 파일이다). 미리보기의 선·모서리·그림자·자막 크기는
  **결과 칸 폭에 대한 비**로 그린다(`--pc-fu` = 결과 칸 폭 ÷ 240): 렌더가 같은 비로 영상에 그려서 화면 크기가 달라도
  비례가 같다. 옛 v1 편집본은 영상 만들기 때 한 번 v2로 다시 저장된다. 편집기가 그리는 것은 세로 한 벌이라, 저장된
  다른 비율(정사각)은 다시 저장해도 그대로 남긴다. 자막 줄은 편집기가 만들지 않는다(AI 자막은 2번 몫): 저장된 줄을
  그대로 두고(편집기에도 보여 준다) 보이는 방식(영상에 새기기·자막 파일·둘 다)·자리만 싣는다. 「바뀌었나」는 숫자 1e-9 여유로, 값이 null인 칸과 없는
  칸을 같게 본다(clip은 자막 없는 편집본을 `"subtitles": null`로 준다).
- **편집 화면은 쇼츠 편집기 구성이다 (POK-389).** 쇼츠 서비스 셋(OpusClip·알파컷·피카클립)과 CapCut·Premiere를 조사해 짰다.
  왼쪽 메뉴는 레이아웃 · 자막 · 텍스트 · 오디오 · 이미지(텍스트·이미지는 준비 중, 「구간」은 타임라인 손잡이와 같은 일이라 뺐다).
  레이아웃은 세로 · 분할 · 중앙 · 크롭 · 가로를 힌트와 함께 목록으로 고르고, 메뉴 패널은 위치 단추로 왼쪽·오른쪽을 바꾼다.
  재생 조작은 **미리보기 아래 줄**에 있다(`TransportBar.tsx`: 5초·1초 뒤로 · 재생 · 1초·5초 앞으로 · 쇼츠 안 시각, 오른쪽 칩은
  구간 반복 · 재생 속도(1×▾) · 「이 장면을 썸네일로」). 구간 끝은 I·O 키와 타임라인 손잡이가 맡고, 확대(− 100% ＋)·접기는 타임라인 머리에 있다.
  타임라인이나 윗줄 눈금을 왼쪽 단추로 누르면 그 시점으로 가고 누른 채 끌면 따라간다. **확대는 캡컷처럼 진짜다**(`zoomedView`): 100%는
  카드에서 잡을 수 있는 범위 전체(손잡이로 구간을 늘릴 자리)이고, 25·50%는 더 넓힐 수 있을 때만 켜진다. 그 위로는 재생 위치 둘레만 보이며 재생하면 창이 따라 넘어간다(창 안을 누르면 그대로). 창 밖으로 나간 구간
  끝은 가장자리 「시작점」「끝점」 표시가 대신하고 누르면 그리로 간다(구간 상자는 자르지 않은 자리로 그려 손잡이도 덮개 밖으로 숨는다).
  가운데 화면에는 판만 있고(위 막대·안전 영역·결과 아래 요약 줄은 걷었다) 영상은 칸 높이만큼 크게, 위만 10px 띄운다.
  타임라인은 자막(있을 때) · 영상(**장면 그림 필름띠**, POK-381의 장면 그림 훅을
  가로 크기로 재사용) · **방송 소리 트랙**(트랙별 **실제 소리 크기 파형**: 미리 듣기로 풀어 둔 소리를 0.05초마다 잰다, 무음은 평평,
  음량 반영, 뺀 줄은 흐리게) 줄이고, 쇼츠 밖은 흐리게 덮는다. 소리 트랙의 **넣기·음량은 트랙 줄 머리에서만** 바꾼다
  (`TimelineTrackRow.tsx`: 스피커 = 넣기, 음량 숫자를 누르면 막대와 50 · 100 · 150%, 좌우로 끌면 1px = 1%, 초점이 있으면 ← → 5%).
  오디오 메뉴에는 그 안내와 준비 중인 음악 · 효과음만 있다(빠른 설정·음량 막대는 같은 값을 두 곳에서 바꾸지 않게 걷었다).
  「썸네일」로 고른 장면은 영상 줄 앞 칸에 남고(필름띠와 같은 장면 그림 훅에서 뽑아 숨은 영상 노드가 하나다) 영상 만들기 창의 추천 장면
  맨 앞 「편집기에서 고름」으로 골라져 열린다(편집 기록에는 안 남는다). **영상 만들기 창은 정보 · 썸네일 · 공개 탭**이고 창 크기는
  고정이다: 탭 내용과 왼쪽 미리보기 열이 각각 안에서 스크롤한다(낮은 화면에서 미리보기 아래가 잘리지 않게). 입력 칸의 Enter로는 보내지 않는다.
  **트랙별 미리 듣기**(`trackAudio/`): 재생 서버 영상은 첫 소리 트랙만 남겨서(`media/internal/playback/producer.go`) 영상이 받으려는 창의
  **녹화 조각**(소리 트랙 전부, 렌더가 읽는 그 파일)을 clip `POST …/segments/audio-access`로 영상과 함께 받기 시작해 트랙마다 풀고(`fmp4Audio.ts`: 라이브러리
  없이 moov·moof를 읽어 AAC를 ADTS로 감싼다, 트랙 번호 = 파일 순서 = 렌더의 `[0:a:N]`), 영상 노드를 따라 튼다(`trackAudioPlayer.ts`:
  재생·멈춤·이동·배속을 따르고 0.08초 넘게 벌어지면 다시 맞춘다). 따라가는 동안 영상 소리는 끈다. 트랙을 끄거나 음량을 바꾸면 바로 들린다
  (소리 트랙이 하나뿐인 녹화도 재생기로 틀어 그 음량이 들린다).
  조각은 영상까지 든 파일이라 받는 데 수십 초가 걸린다(3분 구간 ≈ 150MB). 그동안 음량이 영상 소리와 같으면(첫 트랙만 100%: 새로 연
  편집본) 영상 소리를 그대로 두고, 다르면 끈다(뺀 트랙이 섞인 최종 믹스가 들리지 않게). 창을 다시 받는 동안은 앞 창 재생기가 이어 튼다.
  조각 하나라도 실패하면 받던 나머지도 멈추고, 60초 동안 조각이 하나도 안 오면 「못 부름」이다(느려도 오고 있으면 끊지 않는다).
  받는 사이 서명 주소(5분)가 만료되면(403) 주소를 새로 받아 그 조각부터 이어 받는다. 받은 조각을 하나라도 못 풀면(깨짐 · 모르는 AAC)
  그 자리를 무음으로 두지 않고 「못 부름」이다.
  배속: 소리 노드의 배속은 음높이까지 바꾼다. 음량이 영상 소리와 같으면 배속 중에는 영상 소리(음높이 그대로)로 듣고, 음량을 바꿔 뒀으면
  그 음량이 들리는 재생기를 두어 음높이가 배속만큼 바뀐다.
  이어진 조각끼리는 한 번에 푼다(조각마다 끊어 풀면 4초마다 이음매 소리). 풀어 둔 소리는 24kHz다(3분 20초 × 트랙 여섯의 메모리).
  🔴 **못 부르면 영상 소리(최종 믹스)로 돌아가고 미리보기 아래에 「트랙별 미리 듣기를 못 불러왔어요」를 띄운다**: 소리 문맥을 못 만들거나,
  주소·조각을 못 받거나, 모르는 AAC 모양(HE-AAC 등 ADTS로 못 옮기는 것)일 때. 받는 중이거나 녹화가 없는 구간은 알리지 않는다.
  덜 올라온 조각 자리는 소리 없이 둔다.
  🔴 **배포 조건: 조각 창고에 웹 주소를 허락하는 CORS(GET·HEAD)가 있어야 한다** (화면이 조각을 `fetch`로 받는다. 로컬 LocalStack도 같다,

  플랫폼 태그는 켜진 것을 모두(「치지직 · SOOP」), 제목 · 카테고리 · 시청자 수 · 그래프 · 내 채널 이름(치지직 채널 이름 · SOOP
  닉네임)은 대표 플랫폼 하나에서 가져온다. 플랫폼 구분 없는 가장 새 관측(`latest`)을 그대로 쓰면 SOOP로만 켠 방송에 묶음에 남은
  치지직 값이 섞였다. 위임받은 방송(편집자)에는 스트리머의 플랫폼 채널 이름이 실려 오지 않아 이름을 비운다.

**404 계약.** `app/not-found.tsx` 하나가 두 경우를 다 받는다 — 어떤 경로에도 안 걸린 주소, 그리고 상세 화면이 `notFound()`를 던진 경우. **자원이 없으면(만료·삭제·권한 회수) 상세 화면은 `notFound()`를 던져 이 화면을 재사용한다** — 「없음」과 「만료」를 문구로 가르지 않는다 (POK-204 · ADR-045). 루트에 두는 게 조건이다: `(dock)` 안에 두면 `AuthGuard`가 먼저 걸려 비로그인 사용자에게 404 대신 `/login`이 뜬다.

### 환경변수 (`.env.example` → `.env.local`)

| 변수                                  | 값(로컬)                 | 용도                                                                                                         |
| ------------------------------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------ |
| `AUTH_API_URL`                        | `http://localhost:8082`  | auth 서버 — `/api/auth/*` rewrites 프록시 대상                                                               |
| `CLIP_API_URL`                        | `http://localhost:8081`  | clip 서버 — `/api/clip/*` rewrites 프록시 대상                                                               |
| `NEXT_PUBLIC_GOOGLE_CLIENT_ID`        | 구글 OAuth 클라이언트 ID | 로그인 동의 URL 조립 — 백엔드 `GOOGLE_CLIENT_ID`와 같은 값                                                   |
| `NEXT_PUBLIC_MEDIA_STUB_URL`          | 스텁 m3u8 주소           | 플레이어 개발용 정적 세그먼트 ([`infra/compose/stub/`](../infra/compose/stub/))                              |
| `NEXT_PUBLIC_MEDIA_LIVE_BASE_URL`     | LL-HLS 베이스            | 진짜 미디어 서버 (`{base}/{영상 경로 키}/index.m3u8`, POK-233)                                               |
| `NEXT_PUBLIC_MEDIA_PLAYBACK_BASE_URL` | 녹화 재생 (비워도 됨)    | 다시보기·편집기 미리보기 (`{base}/playback/{키}/list`·`/get`, POK-317). 로컬은 `http://localhost:3000/media` |
| `MEDIA_PLAYBACK_ORIGIN`               | `http://localhost:9996`  | 로컬 전용 재생 서버. `/media/playback` 라우트가 넘긴다(비면 404). prod · dev는 비운다                        |
| `NEXT_PUBLIC_POSTHOG_KEY`             | 비움                     | 사용 통계(PostHog) 프로젝트 공개 키 — 비면 SDK를 불러오지 않음 (POK-356)                                     |
| `NEXT_PUBLIC_POSTHOG_HOST`            | 비움                     | PostHog 수집 주소(운영 `https://us.i.posthog.com`) — 규칙은 `docs/ANALYTICS.md`                              |
| `NEXT_PUBLIC_POSTHOG_REPLAY`          | 비움                     | `on`일 때만 세션 녹화(POK-358) — 콘솔 녹화 토글도 켜야 시작                                                  |

서버 주소는 **코드에 하드코딩하지 않는다** — env 참조만. env가 없으면 해당 rewrites가
아예 걸리지 않으므로 백엔드 없이도 **기동·빌드는 된다**. 다만 env가 있는데 백엔드가 안
떠 있으면(재시작 중 포함) 그 경로의 요청은 프록시 연결 실패로 **500**이 난다 — dev 로그의
`Failed to proxy ... AggregateError`가 그 신호다 (POK-217,
[트러블슈팅](../docs/dev-environment.md#dev-프록시-트러블슈팅-pok-217)). rewrites 대상은
**빌드 시점에 굳는다** — `next start`는 실행 시점 env를 읽지 않으므로, 운영 빌드의 프록시
대상을 바꾸려면 다시 빌드해야 한다. 백엔드 로컬 기동은
[`docs/dev-environment.md`](../docs/dev-environment.md).

### 컨테이너 이미지 (`Dockerfile`)

운영(prod)에서는 공개 ALB 뒤 ECS Fargate 태스크가 이 이미지를 돌린다. `output: 'standalone'`
빌드의 `server.js`를 비root 사용자 `node`로 띄우며, 포트는 `3000`이다. 올리는 절차는
[`prod-artifacts.md`](../infra/terraform/runbooks/prod-artifacts.md)를 따른다.

```bash
docker build --platform linux/<태스크 아키텍처> -t pokeclip-web \
  --build-arg AUTH_API_URL=… --build-arg CLIP_API_URL=… \
  --build-arg NEXT_PUBLIC_GOOGLE_CLIENT_ID=… \
  --build-arg NEXT_PUBLIC_MEDIA_LIVE_BASE_URL=… \
  --build-arg NEXT_PUBLIC_MEDIA_PLAYBACK_BASE_URL=… \
  web
```

**환경 값은 전부 빌드 인자다 — 실행 시점 env로는 바뀌지 않는다.** rewrites 대상은
`next build`가 `.next/routes-manifest.json`에 박고, `NEXT_PUBLIC_*`는 번들에 인라이닝된다
(2026-10-23 실측 — 빌드 때와 다른 `AUTH_API_URL`·`CLIP_API_URL`을 주고 `next start`와
`server.js`를 띄워도 빌드 때 주소로 프록시했다). 그래서 환경마다 따로 빌드한다.

| 빌드 인자                             | 비면                   | 값                                  |
| ------------------------------------- | ---------------------- | ----------------------------------- |
| `AUTH_API_URL`                        | **빌드 실패**          | auth 서버 내부 주소 (rewrites 대상) |
| `CLIP_API_URL`                        | **빌드 실패**          | clip 서버 내부 주소 (rewrites 대상) |
| `NEXT_PUBLIC_GOOGLE_CLIENT_ID`        | **빌드 실패**          | 백엔드 `GOOGLE_CLIENT_ID`와 같은 값 |
| `NEXT_PUBLIC_MEDIA_LIVE_BASE_URL`     | **빌드 실패**          | LL-HLS 베이스                       |
| `NEXT_PUBLIC_MEDIA_PLAYBACK_BASE_URL` | **빌드 실패**          | 녹화 재생 서버                      |
| `NEXT_PUBLIC_POSTHOG_KEY` · `_HOST`   | 사용 통계 꺼짐         | 운영 값은 `.env.example` 주석       |
| `NEXT_PUBLIC_POSTHOG_REPLAY`          | 세션 녹화 꺼짐         | `on`일 때만 켜짐                    |
| `NEXT_PUBLIC_LANDING_URL`             | `https://pokeclip.com` | 랜딩 주소                           |

`NEXT_PUBLIC_MEDIA_PLAYBACK_BASE_URL`은 prod 이미지가 다시보기·편집기 미리보기가 꺼진 채 나가지 않게
필수로 둔다(로컬 개발은 위 환경변수 표대로 비워도 된다). prod 값은 I2-2에서 이것도 함께 정한다.

선택 인자는 비어도 빌드가 멈추지 않으므로, 이름을 잘못 적으면 그 기능이 조용히 꺼진 채 빌드된다.

- `NEXT_PUBLIC_MEDIA_STUB_URL`은 받지 않는다 — 배포 빌드에서는 반드시 비어야 한다. 같은 이유로
  `.dockerignore`가 `.env*` 파일을 빌드 컨텍스트에서 뺀다(`.env.local`이 섞이면 `next build`가
  읽어 굳힌다).
- 실행 시점 env는 `PORT`(기본 `3000`)·`HOSTNAME`(기본 `0.0.0.0`)·`KEEP_ALIVE_TIMEOUT`(기본 `65000`ms)
  셋이다. `KEEP_ALIVE_TIMEOUT`은 ALB idle timeout보다 길어야 한다 — SSE 때문에 M8에서 ALB idle을
  늘리면 이 값도 그보다 크게 준다.
- 헬스체크는 `/api/ping`이다(앱이 직접 답해 백엔드 상태와 무관). 이미지에 `HEALTHCHECK`로 넣어
  뒀다.
- `pnpm start`(`next start`)는 standalone 설정에서 경고를 내지만 동작은 한다. 운영과 같은 꼴로
  띄우려면 Dockerfile이 하는 대로 `public`·`.next/static`을 standalone 폴더로 옮긴 뒤 띄운다
  (standalone은 두 폴더를 싣지 않는다):

  ```bash
  cp -r public .next/standalone/ && cp -r .next/static .next/standalone/.next/
  node .next/standalone/server.js
  ```

### 세션·토큰 저장과 다중 탭

- access(30분)는 **메모리에만**, refresh(14일)만 `localStorage`(`pc-auth`)에 둔다 — `stores/auth.ts`. localStorage의 refresh가 **정본**이다.
- 탭 사이 전파는 `BroadcastChannel('pc-auth')`: `login`(새 세션 — 받는 탭은 쿼리 캐시를 비운다) · `rotate`(같은 세션의 refresh 회전 — 받는 탭은 **내 refresh의 직계 후속일 때만** access까지 이어받고 캐시는 그대로 둔다) · `logout`. 받는 탭은 localStorage를 쓰지 않는다.
- `storage` 이벤트는 **폴백**이다 — 100ms 뒤 정본을 다시 읽어 채널이 이미 맞췄으면 아무것도 하지 않고, 아니면 이전 계약대로 access를 비우고 캐시를 지운다(회전인지 계정 교체인지 알 수 없으므로). 탭이 다시 보일 때(`visibilitychange`·`pageshow`)와 **회전 요청 직전**에는 지연 없이 같은 동기화를 한다 — 메시지를 놓친 탭이 묵은 refresh로 회전하면 10초 유예 밖 재사용이라 서버가 전 세션을 끊는다. 정본을 읽을 수 없거나 저장이 실패한 탭은 동기화에서 빠진다(메모리 세션은 새로고침까지 유지).
- 회전은 `navigator.locks`(`pc-auth:refresh`)로 **탭 사이에서도 한 번에 하나만** 돈다 — 두 탭이 같은 refresh로 동시에 회전하면(탭 여러 개를 한꺼번에 복원) 진 쪽이 401을 받는데 클라이언트는 그걸 만료와 구분할 수 없기 때문이다. 락을 얻은 뒤 정본이 바뀌어 있으면 보내지 않거나 정본 토큰으로 회전한다. 락이 없는 환경에서만 401 뒤 0.5초 동안 옆 탭의 `rotate`를 기다리고, 그래도 정본이 바뀌어 있으면 세션을 접는 대신 정본을 채택한다.
- **세션 세대 (POK-222).** 응답이 늦게 오는 작업은 시작할 때 `captureSession()`으로 세션을 적어 두고, 응답이 오면 「아직 같은 세션인가」를 묻는다. 세대는 로그인·로그아웃(이 탭이든 다른 탭이든)과 폴백 동기화에서 오르고, 회전에서는 안 오른다. 채널 연동 세 플랫폼(치지직·유튜브·SOOP)의 시작·콜백·해제가 이것으로, 다른 탭이 계정을 바꾼 뒤 도착한 결과를 토스트·집계·캐시·화면 이동 어디에도 반영하지 않는다(앞 계정의 채널명이 다음 사람에게 보이거나, 캐시에 되심은 「미연동」이 다음 사람의 연동을 덮거나, 앞 계정 몫의 동의 화면으로 보내는 것을 막는다). 「로그인이 필요해요」 화면은 지금 상태라 그대로 띄운다. 폴백은 회전이었어도 올리므로, 메시지를 놓치거나 늦게 받은 경우(두 탭이 한꺼번에 회전할 때 회전 직전 동기화가 옆 탭의 메시지보다 저장소를 먼저 보는 경우 포함)에는 같은 사람의 결과 토스트도 빠진다(연동 자체와 화면 상태는 서버에서 다시 읽어 맞다). 세대는 페이지가 뜬 뒤의 변경만 본다: 동의 화면(치지직·구글·SOOP)에 가 있는 동안 다른 탭이 계정을 바꾸면 콜백은 새 계정으로 교환하고, 서버가 state를 회원에 묶어 두어 「연동 요청을 확인할 수 없어요」로 막는다(다른 계정에 붙지는 않는다).
- **뮤테이션은 전부 `useSessionMutation`으로 만든다 (POK-424).** 요청을 보낼 때의 세션을 적어 두고, 응답이 왔을 때 세대가 바뀌었으면 성공·실패 콜백(캐시 반영·토스트·화면)을 건너뛰고 끝맺음 콜백(모달 닫기·다시 읽기)만 부른다. 버린 응답은 오류 상태로도 남기지 않는다. 연동 6곳(시작·해제)의 개별 확인을 이것으로 합쳤고, 페어링 코드 발급(앞 계정의 코드가 다음 사람 화면에 뜨면 그 코드로 앞 계정의 키를 받는다)·편집자 초대·내보내기·초대 취소·초대 수락·거절·채널 나가기·표시 이름 저장이 같은 규칙이다. react-query의 `useMutation`을 직접 쓰면 ESLint가 막는다. 뮤테이션이 아닌 늦은 응답(연동 콜백 화면 셋)은 위처럼 `captureSession()`을 직접 쓰고, 프로필 사진 올리기는 회원 번호 대조로 막는다.
- **알려진 한계**: BroadcastChannel이 없는 환경과 구버전 번들 탭이 섞인 창에서는 폴백만 동작해 회전 핑퐁(POK-211)이 재발할 수 있다.

## 규칙

- **DS 소비 방식**: 디자인 시스템은 `src/ui/` 소스를 `@/ui`로 직접 import한다.
  별도 빌드 없음 — DS 수정은 `next dev` HMR로 즉시 반영된다.
- **전역 CSS**: 토큰·폰트·리셋은 `@/ui/styles/global.css` 하나만 루트 레이아웃에서
  임포트한다. 컴포넌트 스타일(CSS Modules)은 각 컴포넌트가 스스로 import한다.
- **클라이언트 경계**: DS 소스에는 `'use client'`가 없다. 인터랙티브 DS 컴포넌트
  (ThemeProvider, 훅/핸들러 사용 컴포넌트)는 `'use client'` 파일에서 렌더링한다.
- **design-sync**: 기존 도구는 `packages/ui/dist/design-system.css`를 소비했다 —
  플랫화로 dist가 사라졌으므로 다음 사용 시 config 재설정이 필요하다.

## 재생에서 조심할 것

LL-HLS 플레이어는 **catch-up을 꺼야 한다.** 켜져 있으면 되감기 중에 플레이어가
자기 마음대로 라이브 끝으로 점프한다.

재생 규약의 정본은 [`contracts/`](../contracts/) 계약3이다.

## 편집자가 하는 일의 본질

**화면에서 "여기부터 여기까지"를 고르면, 그 시각 두 개가 서버로 간다.**
영상을 보내는 게 아니다. 그래서 편집을 오래 붙잡고 있어도, 라이브 버퍼에서 그 구간이
빠져나가도 문제가 없다 — 원본은 전부 S3에 있다.

이게 되려면 플레이어가 **지금 재생 중인 지점의 절대 시각**을 알아야 한다.
