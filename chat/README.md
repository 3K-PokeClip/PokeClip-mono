| | 역할 |

수집(상시 연결)과 판별(계산)은 성격이 달라 분리한다.

## 왜 채팅인가

**채팅을 "시청자의 실시간 반응 투표"로 쓴다.** 이 서비스의 핵심 차별점이다.

팀 실측(실경기 채팅 18,112건)으로 확인한 것 — 메시지 수보다 **고유 채터 수의 급증**이
더 깨끗한 신호다. 1인 도배는 메시지 수만 올리고, 진짜 하이라이트는 눈팅층이 동시에 입을 여는 순간이다.

알고리즘 상세는 `PokeClip-LLM-WIKI`의 ADR-011과 하이라이트 연구노트에 있다.

## 판별 결과는 어디로 가나

Clip Service에 하이라이트 후보를 넘긴다. 화면에 그리는 것은 2번이 만드는 대시보드다 —
경계는 [`contracts/`](../contracts/)에서 만난다.

## 미정

**언어가 아직 확정되지 않았다.** 팀 문서(ADR-007)는 Node·TS 기준이고 기존 수집기 자산 재사용을
전제하지만, 담당이 3번으로 옮겨지면서 Spring 재작성 안이 논의 중이다.

Spring으로 확정되면 이 폴더는 [`services/`](../services/) 아래 모듈로 흡수한다.
