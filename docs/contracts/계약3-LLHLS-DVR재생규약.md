# 계약3 — LL-HLS/DVR 재생 규약 (1번 → 2번)

> **인터페이스 계약3** (11_역할분담 계약 9종 중 하나). 방향 `1 → 2` = 1번(인프라/미디어)이 정의해 2번(프론트)에게 전달한다. **2번은 서버 내부(MediaMTX·티어링·S3)를 몰라도 이 문서만으로 플레이어를 만들 수 있어야 한다.** 파라미터 근거: ADR-020 (PokeClip-architecture repo). 확정판 2026-07-31 — 로컬 검증 실측값 반영.

## 1. 재생 URL

```
https://media.pokeclip.com/live/{streamId}/index.m3u8
```

- 스트림 없음/종료 → **404**
- **인증**: CloudFront 서명 쿠키 필요. Auth 서비스(3번)가 `Domain=.pokeclip.com`으로 발급하므로 **브라우저가 자동 첨부**(프론트가 헤더로 수동 첨부할 것 없음). 만료 전 갱신 호출은 프론트 책임(현 설계 ~5분).
- **CORS**: 앱(`app.pokeclip.com`)과 미디어(`media.pokeclip.com`)가 다른 오리진 → 쿠키 전송되도록 credentials 설정 필요.

### 로컬 개발 매핑 (docs/dev-environment.md의 compose 환경)

| 용도 | URL |
|---|---|
| 정적 스텁 (뼈대·시킹 UI 개발) | `http://localhost:8080/live/stub/index.m3u8` |
| 진짜 LL-HLS (MediaMTX, 송출 필요) | `http://localhost:8888/{streamId}/index.m3u8` |

로컬은 인증·서명 쿠키 없음. MediaMTX는 `index.m3u8` 요청에 302(세션 파라미터 부여)를 줄 수 있으니 플레이어(hls.js)가 리다이렉트를 따르게 둘 것(기본 동작).

## 2. 매니페스트

- **LL-HLS** — `EXT-X-PART`, `EXT-X-PRELOAD-HINT`, `EXT-X-SERVER-CONTROL:CAN-BLOCK-RELOAD=YES` 포함
- master playlist → media playlist 2단 구조
- **세그먼트 4초 / part 0.5초**
- **PART-HOLD-BACK = 1.33초 (2026-07-31 로컬 실측: PART-TARGET 0.533s × 2.5)** — 플레이어는 매니페스트가 주는 값을 그대로 따를 것. 인프라 변경으로 값이 바뀔 수 있으며 그 경우 이 문서를 갱신한다.
- 오디오는 **라이브에서 단일 트랙**(6트랙은 녹화·클립 렌더 전용 → 플레이어에 오디오 트랙 선택 UI 불필요)
- **화질 선택(ABR) 없음 — MVP 단일 화질.** 컨트롤바에 화질 설정 UI 불필요(추후 트랜스코드 도입 시 계약 갱신).

## 3. DVR

- **되감기 창 = 최대 1시간**(세그먼트 900개). UI 표시 상한도 `1:00:00`.
- 세그먼트 URL은 **매니페스트가 주는 대로 따라갈 것.** 세그먼트당 정규 URL 하나 영구 고정(핫/콜드 티어는 서버 내부에서 해소 — 프론트 관여 없음, URL이 시간에 따라 안 바뀜).
- seek 정밀도 ~2초(GOP 2초).

## 4. 플레이어 요구사항 ⭐ (핵심 — 안 지키면 "DVR이 안 되는" 것처럼 보인다)

실측으로 확인된 사항.

1. **catch-up(라이브 엣지 강제 재동기화)을 끌 것.**
   - hls.js: `liveMaxLatencyDurationCount` 매우 크게(예 `1e9`), `lowLatencyMode: true`, `backBufferLength`를 DVR 창 이상.
   - 끄지 않으면 **뒤로 seek해도 라이브로 튕긴다.**
2. **마우스 시크와 키보드 시크를 동일하게 처리할 것.**
   - 커스텀 시크바를 만들고 `input` 핸들러에서 **`currentTime = 절대위치` 설정만** 할 것. **어떤 seek 후에도 "라이브로 맞추는" 코드를 호출하지 않는다.** (기본 플레이어는 "클릭 후 라이브 재동기화" 버릇이 있어 키보드는 되고 마우스는 튕기는 현상이 난다)
3. **라이브 복귀는 명시적 `LIVE` 버튼으로만.**
4. **시크바·시간 표시는 `seekable` 범위 기준**, 상한은 DVR 창(1h).
5. **되감기 버튼 단위(예 −10초)는 `currentTime -= N`으로 자유롭게** — 세그먼트 길이와 무관.
6. **채팅은 재생 위치 기준 렌더**(타임스탬프 + `currentTime` 정렬). 라이브=시차 보정, 되감기=그 시점 채팅 재생.

## 5. 지연 기대치

- LL-HLS 정상 경로 **2~4초**(기능명세 "2~5초"). 폴백(일반 HLS) ~12초.
- **0초급은 구조적으로 불가**(HTTP 풀 + 플레이어 3파트 hold-back). 지연을 좇지 말고 §4-6 시차 보정으로 UX를 맞춘다.

## 6. 미확정 (인프라 구축 시 1번이 채움)

- 실제 도메인(`media.*`/`app.*`) · `streamId` 형식
- 서명 쿠키 갱신 엔드포인트 경로·만료(3번 Auth 제공)
- 에러 응답 상세(권한 없음 403 vs 스트림 없음 404) · 재시도 정책
