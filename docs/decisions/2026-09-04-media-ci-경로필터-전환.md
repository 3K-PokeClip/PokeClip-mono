# ADR-0004: media-ci를 워크플로 레벨 경로 필터로 되돌리고, media-gate 필수 체크를 뗀다

날짜: 2026-09-04(착수 09-03) / 상태: 확정 / 관련: 위키 ADR-013(인프라 — 모노레포 "CI 경로 필터로 변경 서비스만 빌드" 원칙. 이 ADR이 media를 그 원칙으로 되돌린다),
위키 ADR-041(브랜치 전략 — 4절 보호 표·5절·6절·롤백 절이 이 ADR로 정정됨), POK-75(media-ci 3층 구조 도입 — 이 ADR이 그 전제를 폐기한다),
ADR-029(커밋·PR 프리픽스 폐기)

## Context

media-ci는 POK-75 이후 세 잡(changes → check → media-gate)으로 돌았다. `media-gate`가 main·develop 브랜치
보호의 필수 체크였기 때문이다 — GitHub은 워크플로 레벨 `paths:`로 스킵된 워크플로의 체크를 Pending으로
남기고, 필수면 머지를 막는다(공식 문서: "If a workflow is skipped due to path filtering … checks associated
with that workflow will remain in a 'Pending' state. A pull request that requires those checks to be successful
will be blocked from merging." — https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow,
2026-09-03 확인). 그래서 paths 대신 잡 레벨 `if:`로 검사를 거르고, 항상 뜨는 집계 잡을 필수 체크로 삼았다.

그 결과 **모든 PR**에 `media-ci`가 나타났다. 비싼 검사(gofmt·lint·vet·race test·커버리지)는 media가 바뀐
PR에서만 돌았지만(실측: web PR #157·services PR #151 모두 check=skipped), `changes`·`media-gate` 두 잡이
3~4초씩 팀원 PR의 체크 목록에 매번 떴다. 팀원(2번·3번)이 "자기 영역 PR에 media CI가 돈다"고 불편을 말했다.
문제는 비용이 아니라 **팀 경계**다.

필수 체크와 paths는 양립하지 않는다. 팀원 PR에서 media-ci를 완전히 없애려면 `media-gate`를 필수 체크에서
빼야 한다.

## Decision

1. `media-ci.yml`을 web-ci와 같은 **워크플로 레벨 `on.pull_request.paths:`** 로 바꾼다. 감지 정의역은
   현행 changes 필터와 동일한 세 패턴(`media/**`, `.github/workflows/media-ci.yml`, `docker-compose.yml` —
   media 계약 테스트 2개가 루트 compose를 읽는다). `changes`·`media-gate` 잡과 dorny/paths-filter 의존을
   지운다. `check` 잡 본문은 한 줄도 바꾸지 않는다.
2. main·develop 브랜치 보호의 필수 체크에서 `media-gate`를 뺀다 — main은 `main-source-gate`만 남기고,
   develop은 필수 체크 없음. `enforce_admins`·force push·삭제 금지 등 나머지 보호는 그대로다.
   하위 리소스 `PATCH .../protection/required_status_checks`만 쓴다(`PUT .../protection`은 나머지 설정을
   통째로 대체한다).
3. 순서는 **보호 먼저 해제 → 워크플로 PR 머지**다. 반대로 하면 사라진 `media-gate`를 보호가 기다려
   전 PR이 Pending으로 잠긴다.

kty 확정 2026-09-03(결정 B), 범위 확정 2026-09-04.

## Alternatives Considered

- **A. `changes` 잡을 `media-gate` 안으로 접어 체크 줄 2→1, 보호 유지.** 필수 체크는 지키지만 체크 런이
  여전히 생겨 팀원 PR 목록에 media-ci가 남는다 — 목적 미달. 기각.
- **C. develop 보호에서만 제거, main 유지.** 팀원 일상 PR(전부 develop 대상)의 필수 표시는 사라지나 체크
  줄은 그대로 뜨고, media 파손이 develop에 쌓이다 릴리스 PR에서 한꺼번에 막혀 릴리스 전체가 잠긴다. 기각.
- **D. 코드는 두고 팀에 설명만.** 3~4초·비용 0·차단 0이라는 사실 공유. 불편의 실체가 가시성이라 해소 안 됨. 기각.
- **ruleset "required workflows".** paths 스킵을 통과로 취급하는지 문서로 확인하지 못함. 범위 밖.

## Consequences

**Positive**
- media를 안 건드린 PR에는 `media-ci` 체크 런이 0개 — 팀원 PR 체크 목록에서 사라진다.
- dorny/paths-filter 의존과 집계 잡이 사라져 워크플로가 229행 → 172행으로 준다. 검사 본문은 동일.
- paths를 쓰는 워크플로가 web-ci·services-deploy·media-ci로 통일된다(ADR-013 원칙).

**Negative / 감수한 것**
1. **내용을 검사하는 필수 체크가 저장소에 0개가 된다.** media 코드가 빨간불이어도 머지가 기계적으로 막히지
   않는다. mono 머지는 kty 승인 후에만 하므로, 머지 전 초록불 눈확인이 운영 대체다(kty 승인 트레이드오프).
2. paths는 PR의 변경 파일 3,000개까지만 본다(https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax).
   그 뒤에 놓인 media 파일은 감지되지 않아 워크플로가 안 돌고, 필수 체크도 아니라 **검사 없이 머지된다(fail-open)**.
   완화는 대형 PR 분할뿐이다.
3. 감지 정의역 세 패턴은 수동 유지다. media 테스트가 media/ 밖 파일을 새로 읽게 되면 paths도 늘려야 한다(주석이 방어).
4. `claude-code-review.yml` 31행 주석(낡은 보호 목록)은 이번에 고치지 않는다 — 그 액션은 PR의 워크플로
   파일이 기본 브랜치(develop) 사본과 동일해야 실행하므로, 고치면 다음 릴리스 전까지 main에서 따는
   hotfix PR의 Claude 리뷰가 거부된다. 본문 주장("이 체크는 필수가 아니다")은 참이고 괄호 목록만 낡음.
   다음에 그 파일을 고칠 때 정리한다(kty 확정 2026-09-04).
5. main 사본은 다음 정기 릴리스까지 옛 3층 media-ci를 유지한다. hotfix PR(base=main)에 `changes`·
   `media-gate`(media 변경 시 `check`까지)가 보이지만 보호에서 빠져 머지에 영향이 없다.
6. **롤백**은 정방향의 역순이다 — 브랜치 상태별로: main이 아직 옛 3층이면 develop에만 revert PR을 머지하고,
   main에도 새 구조가 들어간 뒤면 **양 브랜치(develop + main hotfix)** 에 머지한다. 어느 경우든 `media-gate`
   체크 런이 실제로 생기는 것을 각 브랜치 대상 PR에서 확인한 뒤에만 보호를 재등록한다
   (`_workspace/prot-*-before.json` 스냅샷의 `strict`·`checks`만 추출한 최소 PATCH). 한쪽만 되돌리고
   재등록하면 다른 쪽 PR이 영구 Pending이 된다. 재등록 순간 열려 있던 PR은 BLOCKED가 되므로 새 커밋
   push 또는 close/reopen으로 해소한다. 상세는 볼트 런북 `롤백-media-ci-머지게이트.md`.
