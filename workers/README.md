# workers — 잡을 받아 처리하는 일꾼들

## 무엇이 들어가나

| 폴더 | 하는 일 | 담당 |
|---|---|---|
| `render/` | S3 조각을 이어붙이고 FFmpeg으로 잘라 클립을 만든다 | 1번 |

## 워커란

**요청을 받아 바로 답하는 서버가 아니다.** SQS 우편함에서 "이거 해줘" 쪽지를 꺼내
처리하고 결과를 알리는 쪽이다.

```
Clip Service ──쪽지──▶ [ SQS ] ──쪽지──▶ 워커
```

렌더는 몇 분씩 걸린다. 사용자를 기다리게 하지 않으려고 이렇게 나눈다.

## 반드시 지킬 것 — 같은 쪽지가 두 번 온다

SQS는 **at-least-once**다. 안 오는 것보다 두 번 오는 게 낫다는 설계라, 같은 잡이 중복 배달될 수 있다.

**모든 워커는 "이미 한 일이면 그냥 넘어간다"를 넣어야 한다.** 없으면 같은 영상이 두 번 렌더되고,
YouTube에도 두 번 올라간다.

## DB를 직접 보지 않는다

워커는 PostgreSQL에 붙지 않는다.

| 이유 | |
|---|---|
| 결합 | DB 구조가 바뀔 때마다 남의 코드가 깨진다 |
| 언어 | 언어가 다르면 어차피 엔티티를 공유할 수 없다 |
| 수명 | 잡 하나 하고 죽는데 커넥션을 잡고 있으면 낭비다 |

필요한 값은 **잡 메시지에 담아 보내고**, 민감한 값(YouTube 토큰 등)은
[`contracts/api/internal.yaml`](../contracts/api/internal.yaml)의 내부 API로 그때 받아 간다.

토큰을 SQS 메시지에 넣으면 안 된다 — 로그에 찍히고 DLQ에 남는다.
